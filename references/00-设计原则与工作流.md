# 课程设计原则与工作流

## 从需求到证据的链路

每门课应有一条可追溯链：

`学习者需求 → 可观察成果 → 评价证据 → 教学与练习 → 反馈/补救 → 迁移与复习`

推荐先设计成果与评价，再编排活动，借鉴 Understanding by Design（UbD）和建设性对齐。课程地图颗粒度按规模选择：短公开课可用目标表；多周课程应增加模块、先修图和覆盖矩阵。框架指导思考，不替代学科判断。

## 用户资料摄取与知识蒸馏工作流

当用户上传既有课程材料，或指定竞品/同行/最佳实践时，先把资料看作“证据和原料”，不要立刻改写成课程。按 `references/10-资料蒸馏与对标模板.md` 建来源台账、抽取知识卡、标注授权/隐私与来源锚点，再聚合成概念地图。

### 四层分离

1. **源材料层**：来源原话/数据/结构，保留页码、章节、时间戳、URL 锚点；遵守合理引用和用户授权范围。
2. **蒸馏层**：用自己的语言总结核心原则、流程、例证、边界、误区和相互关系。不能把推断写回成原作者明确主张。
3. **教学层**：判断哪些内容学员必须会、先学什么、怎样示范和练习，如何测达成。竞品课的编排只能是设计参考，需结合学习者重做。
4. **交付层**：把经用户确认的课程架构转化为PPT、逐字稿、练习纸、答案量规、海报与证书等一致文件。

每个节点使用可追溯状态：`已从资料提取`、`多源印证`、`外部补充`、`专业推断`、`冲突待核`、`用户待确认`。同一主张可能有多种状态/来源，不以材料数量替代来源质量。

大批资料先对账：登记总数必须等于各互斥读取状态之和；明确处理批次、读取方法、已覆盖范围和未处理队列。扫描/OCR、视频/ASR、表格抽取等自动识别需标识质量；只依赖自动识别且会影响课程结论的内容应复核原件或标“待核”。

### 轻量对话协议

完成初步资料盘点后，回述 5 点：

- 我理解的课程目标与最终学习者；
- 你给的资料里最重要的 3–7 个知识模块/教学机制；
- 哪些来自用户自有材料，哪些来自公开同行/竞品，哪些为外部补充；
- 明显重复、冲突、过期、缺证据或未覆盖的地方；
- 课程结构初稿及我采用的假设。

随后只问最多 3 个高价值问题，例如：

1. 这门课希望学员最终独立完成什么作品/任务？
2. 哪些模块必须保留、哪些是你不希望采用的同行做法？
3. 课程的受众、时长或招生产品有哪些硬边界？

如果用户已经在对话里回答，就直接采用并指出如何影响设计，不重复询问。用户不回应时，按合理假设继续，把未决项标记在总案与索引里；不要因为可选偏好停摆。

### 知识库结构验收

- 主题范围、包含/不包含和目标学员明确。
- 目录层级稳定：知识域/模块/单元/知识卡；课程短小则适当压缩，不强凑层数。
- 每个核心知识卡至少有定义、为什么重要、步骤/判断、例子或反例、误区、边界、先修、可观察表现、练习/评价、来源和状态。
- 每个核心技能知识卡还要能落地教学：学员常见错误、讲师示范、带支架到独立/变式的递进练习、反馈后重试、达标/未达标样例、迁移练习。
- 模块之间标出先修/并列/递进/应用关系；同一节点重复出现时说明层级升级。
- 用户给出的课程经验、公开对标和独立权威来源彼此分栏，不把个人经验伪装为研究结论，也不把市场声量当教学有效性。
- 有争议或证据薄弱的点以研究任务/课堂讨论/待验证假设处理，不写成稳固事实。
- 每个用户需求都能追溯到课程模块、目标、课堂活动和评价证据；孤儿知识点说明用途或删去。

## MECE 内容架构

1. 划定范围：课程承诺解决什么问题，不解决什么问题。
2. 从结课表现逆推必要能力，拆为可观察子技能与知识点。
3. 为每个节点标注先修、层级、证据、课次、来源。
4. 检查边界：相邻模块职责不同，避免把同一概念在多个单元重复教而不升级。
5. 检查覆盖：所有用户需求、目标、考试要求均有落点；无目标、无评价、无来源的内容需解释或删除。
6. 让学科专家审查内容本体。MECE 是持续迭代的设计检查，不是“绝对完整”的证明。

## 目标写法

使用：`学习者在[条件/情境]下，能[可观察行为]，达到[质量标准]。`

可观察动词示例：标记、复述、分类、解释、演示、计算、比较、设计、论证、诊断、修订。像“了解、熟悉、掌握”可作为愿景，但不能单独充当验收目标。SMART 用于检查目标，不应强迫所有目标都有数量阈值；开放创造性成果可用质量量规。

## 课程层级与课时估算

- 用真实任务分析切分内容，而不是把总内容等分。
- 估时应包含讲师示范、学员尝试、讨论、反馈、转场和休息。
- 区分同步课时与课后独立学习；说明每周/每课的预期工作量。
- 复杂技能使用先导练习与逐渐撤架；安排累计复习和迁移任务。
- 如果既定时长装不下目标，优先缩小范围、增加课次或设置进阶选修，不能靠压缩练习来掩盖。

## 公开课质量与商业转化

公开课完成后应留下具体成果，例如完成一个诊断、做出一个小作品、掌握一个可迁移步骤。邀请进入后续课程时，提供清晰课程边界、适配条件、投入、价格/权益和无压力退出选项。营销主张需有来源或课程实绩，不制造虚假稀缺、恐惧或未经证实的收入/效果承诺。

评估漏斗需定义事件、来源渠道、时间窗、分母与缺失数据。示例：报名人数、实际到课人数、完成核心练习人数、合格成果人数、自愿咨询人数、购买人数、退款人数。每个比例写明算式；没有数据时保持空白，安排试运行获取基线。

## 迭代

每次试讲后保留：教案版本、目标达成证据、关键误区、学员作品样例（获同意且去标识化）、反馈、耗时偏差与改动理由。优先改进普遍阻断学习的缺口。单次满意度不等同学习效果。
